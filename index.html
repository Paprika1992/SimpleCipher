Как пользоваться сервисом
1
В поле Текст для шифрования введи текст, который хочешь зашифровать.
В поле Желаемая длина шифра введи количество символов, которое ты бы хотел видеть в шифре (это значение будет учтено только если итоговое количество символов в шифре меньше желаемого).
Что это дает?
Эта опция нужна, если ты хочешь, чтобы длина шифра не подсказывала возможные отличия между зашифрованными значениями. Так, текст '10', '10 000' и '10 000 000' будет иметь одинаковое количество символов в зашифрованном виде. В этом случае, потенциальный злоумышленник не сможет сделать вывод, ориентируясь только на количество символов в шифрах, в каком из них меньшее значение, а в каком большее.
В поле Кол-во шифров введи количество шифров, которое сгенерируется по итогам шифрования.
Зачем?
Используя эту опцию, ты можешь визуально сверить насколько отличаются между собой шифры, не смотря на то, что каждый из них будет содержать переданное тобой значение. Это демонстрирует устойчивость алгоритма к частотному анализу.
2
После нажатия на кнопку Зашифровать сгенерируются шифры. Напротив каждого из них будет кнопка Расшифровать. Нажав на ее, шифр прольется в поле Текст для расшифровки в блоке Дешифровки.
В нем же есть кнопка Расшифровать. Нажав на ее, алгоритм отобразит исходное сообщение
3
Соль для шифра предназначена для обеспечения стойкости шифров к взлому. Она гарантирует, что даже в случае заполучения потенциальным злоумышленником зашифрованных сообщений, их не получится расшифровать, не зная соли (вероятность подобрать соль менее 0.00000000001%).
Для генерации соли используй endpoint api/getCipherSalt(подробнее в разделе навигации API), нажми на иконку напротив поля Ключ для шифра формы основной страницы или на кнопку ниже Получить соль.
Несколько важных уточнений
  1. Не используй соль, которую придумал сам, это не безопасно!
  2. При работе с алгоритмом с демонстрационной страницы (где ты сейчас находишься) передавать соль не обязательно. Однако, при использовании api, ресурс будет требовать ее передачу.
  3. Очевидно, ту же соль, что была передана при шифровании, необходимо передать и при дешифровке для получения исходного сообщения. Можно использовать одну и ту же соль для неограниченного количества операций шифрования/дешифрования
  4. И наконец, храни соль отдельно от шифров, которые были зашифрованы с ее помощью.
4
Ключ является необязательным параметром, который имеет схожее значение с солью и еще на несколько порядков усиливает стойкость шифра к взлому. Если соль - это сейф, который защищает твой зашифрованный текст, ключ - это еще один сейф внутри.
К ключу применяются те же условия, которые описаны в подразделе Несколько важных уточнений для Соли выше, кроме того, что ключ необязательно формировать и передавать при работе с api
Для генерации ключа воспользуйся api ендпоинтом api/getCipherKey (подробнее в разделе навигации API), нажми на иконку напротив поля Соль для шифрования формы основной страницы или на кнопку ниже Получить ключ
